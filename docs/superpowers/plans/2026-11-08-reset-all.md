# Reset-All Monitors Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** One confirmed click resets every connected screen to default color and lifts every pin, so the enforcer never repaints afterward.

**Architecture:** A new Tauri command loops connected monitors through the existing per-monitor reset path (clearing each applied record like `reset_monitor_cmd` does) and then clears the whole pin map in the store; the frontend wraps it, reuses the app's confirm-dialog pattern, and reports outcomes via the existing toast.

**Tech Stack:** Rust/Tauri 2, React 19 + TypeScript, Vitest.

**Spec:** `docs/superpowers/specs/2026-11-08-post-meetup-0-8-3-design.md` (§3)

## Global Constraints

- ICC associations are NOT dissociated (spec decision).
- Pins are cleared even when individual monitor resets fail; per-monitor applied records clear only on that monitor's success.
- Confirm dialog copy verbatim: "Reset every connected screen to default colors and remove all pins?"
- Toast summary format (exact): "Reset all: <N ok> OK · <M failed> failed · <P> pins removed"; a failed monitor's own status card shows its individual error.
- No new crates. Gate: `cargo test`, `npm run test`, `npm run build` green.

## Review Focus

- **A pinned monitor in reset-all** must end unpinned with default colors — no reassert within the enforcer tick. Test in Task 2 step 1 (`pinned_cleared_even_if_reset_fails`).
- **Offline (disconnected) monitors** must be skipped without error entries poisoning the batch, but offline pins still lift. Test in Task 2 step 1.
- **Double-click / two sources racing** (tray add later, not here): button must disable while a reset is running. Covered by Task 3 UI step.
- **Zero connected monitors**: button still lifts pins and the toast says "0 monitors reset · N pins removed" — never silently nothing. Test in Task 2 step 1.
- **Failure partial outcomes** (one monitor offline mid-batch, one NVAPI refusing): summary must name the failed monitor but must NOT abort the rest. Test in Task 2 step 1 (`partial_failure_preserves_outcomes`).
